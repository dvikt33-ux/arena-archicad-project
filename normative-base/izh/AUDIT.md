# ИЖС — аудит архитектурно-конструктивных узлов и автоматизации

Дата прохода: 2026-10-01. Целевой профиль: **RU_2027_PLUS**.

## Принцип аудита

Каждый узел проходит повторяющийся цикл:

1. классификация конструкции и условий эксплуатации;
2. проверка актуальной нормативной редакции на 2027+;
3. разделение архитектурного решения, КР-расчета, инженерного расчета и данных изготовителя;
4. построение всех обязательных контуров узла;
5. выбор нативного представления Archicad;
6. проверка возможностей Tapir и safe-bridge;
7. запись только подтвержденных правил;
8. обратный аудит на конфликт, устаревшую редакцию, неверную размерную семантику и ложную автоматизацию.

Правило fail-closed: отсутствие подтвержденного решения означает `blocked / needs_*`, а не применение «типового» значения.

## Цикл 1 — область ИЖС и исходные данные

Подтверждено:

- базовый функциональный документ — СП 55.13330.2016; официальная карточка содержит Изменения №1 и №2;
- Изменение №2 введено 18.06.2023;
- для конструктивного решения СП 55 отсылает к профильным нормам по нагрузкам, основаниям, материалам конструкций, кровлям, инженерным системам и т. п.;
- нормативная база проекта должна применять более новые действующие редакции этих профильных документов через общий профиль `RU_2027_PLUS`, а не замораживаться на ссылочном списке редакции СП 55 от 2023 года.

Результат: `00_scope_inputs_2027.yaml`.

### Запрещено автоматизировать без исходных данных

- тип/размер/армирование фундамента без инженерной геологии и КР;
- несущие простенки, опирания, балки, стропила и анкеровку без расчета;
- толщину утеплителя и окончательный пирог ограждения без тепловлажностной проверки;
- отверстия в несущих конструкциях без КР;
- диаметры, мощности и инженерные шахты без профильного расчета.

## Цикл 2 — алгоритм подбора конструктивной системы

Вместо «выбрать типовой дом» принят pipeline кандидатов:

`scope → ground/foundation → structural load path → thermal/moisture → fire/durability → MEP integration → constructability → optimization`.

Фундамент, стены, перекрытия и кровля сначала существуют как **семейства кандидатов**. Сравнение стоимости/скорости выполняется только после прохождения обязательных нормативных и расчетных ограничений.

Результат: `01_construction_selection.yaml`.

## Цикл 3 — что такое строительный узел

Аудит отверг модель «узел = красивый 2D-фрагмент».

Обязательные независимые контуры:

- передача усилий;
- соединение и крепеж;
- деформации и допуски;
- тепловая непрерывность;
- воздухонепроницаемость;
- парорегулирование;
- защита от объемной воды/гидроизоляция;
- водоотвод и высыхание;
- пожарный контур при применимости;
- акустический контур при применимости;
- коррозионная/биологическая защита;
- инженерные проходки;
- последовательность строительства;
- контроль и обслуживание.

Такой подход соответствует характеру требований СП 55 к надежности, влагозащите, герметизации и деформациям. Для светопрозрачных конструкций дополнительно подтвержден системный подход действующими ГОСТ 34378-2018, ГОСТ Р 59495-2021 и ГОСТ Р 70266-2022.

Результат: `02_node_ontology.yaml`.

## Цикл 4 — представление в Archicad 29

Подтверждено официальной справкой Graphisoft:

- приоритетные сопряжения опираются на Building Material;
- Trim, Merge, Solid Element Operations и Join создают ассоциативные связи;
- Complex Profile — атрибут поперечного сечения для стен/колонн/балок и ряда компонентов; стены/колонны/балки могут использовать offset modifiers;
- Opening — самостоятельный ассоциативный элемент, привязанный к Wall/Slab/Mesh/Roof/Beam, имеет ID/Classifications/Properties;
- source-based Detail содержит взорванные 2D-линии/штриховки и сам Detail работает 2D-инструментами.

Следствие: source Detail — **выходная документация**, не единственный источник истины узла.

Результат: `03_archicad_node_implementation.yaml`.

## Цикл 5 — Tapir vs наш safe-bridge

Проверено по upstream Tapir 1.5.9 (09.09.2026): текущий Tapir имеет широкое покрытие создания/изменения элементов; в релизах 1.5.x подтверждены стены, балки, колонны, плиты, объекты/лампы, Morph, крыши, лестницы, окна/двери, проемы, 2D, MEP, Favorites и другие группы.

В `agent-handoff/src/accollab/connector.py` generic `tapir(name, parameters)` уже позволяет вызывать существующую команду Tapir при известной схеме.

Но `agent-handoff/src/accollab/applier.py` сейчас безопасно применяет в journal path только `primary/modify` как перемещение + отдельные lock/unlock/comment сценарии. Create/delete и изменение геометрии не должны считаться уже решенной безопасной функцией.

### P0 — расширять наш bridge/applier

1. Typed create для основных типов элементов.
2. Typed geometry modify, а не произвольный JSON.
3. Delete с preconditions/receipt.
4. Создание/удаление отношений (например SEO) с read-back.
5. Ownership и approval для Openings.
6. Batch transaction / deterministic ordering / compensation.
7. Расширенный postcondition engine.
8. Runtime handshake Archicad + Tapir + command availability.

### Не форкать Tapir без необходимости

Если upstream уже предоставляет примитив, требуется wrapper/orchestrator и проверка, а не новый Add-On command. Форк/расширение Tapir допустим только после проверки, что нужного Archicad API-примитива действительно нет в текущем наборе команд.

### Пока требует точной проверки схемы перед решением «нужен форк»

- создание/редактирование Complex Profile attribute;
- автоматическое создание Detail/Worksheet и связанных маркеров;
- отдельные типы нативных Trim/Merge/Join отношений помимо подтвержденных SEO/relations механизмов;
- запись всех полей Building Material, влияющих на приоритеты, в актуальной Tapir-схеме.

До проверки исходного кода/схемы Tapir эти функции нельзя помечать `missing` или `available` безусловно.

Результат: `04_tapir_capability_gap.yaml`.

## Цикл 6 — алгоритм генерации узла

Сформирован детерминированный pipeline:

`classify → sources → calculations → contour graph → Archicad mapping → preflight → batch execute → geometric readback → engineering audit → drawing output → release gate`.

Любое изменение host geometry, материала, отверстия, продукта/Favorite, КР/теплотехнического расчета, MEP-трассы или нормативной редакции инвалидирует статус узла и требует повторного аудита.

Результат: `05_node_generation_algorithm.yaml`.

## Цикл 7 — первый каталог узлов ИЖС

Созданы 14 абстрактных семейств:

1. фундамент–наружная стена–цоколь;
2. пол по грунту/плита–наружная стена;
3. кладочная стена–перекрытие;
4. угол/T-стык наружных стен;
5. окно: верх/бок/низ;
6. входная дверь–порог;
7. скатная деревянная кровля–стена/карниз;
8. конек скатной кровли;
9. проходка кровли/дымоход/вентиляция;
10. мокрое помещение: пол–стена–трап;
11. инженерная проходка через стену/фундамент;
12. внутренняя стена–пол–отделка;
13. терраса/крыльцо–наружная стена;
14. внутренняя несущая стена–фундамент.

Для каждого записаны обязательные компоненты/проверки и `never_infer` поля. Числа, требующие расчета или конкретной системы, намеренно не внесены.

Результат: `06_canonical_nodes_v1.yaml`.

## Финальный аудит текущего цикла

### Подтверждено

- подход пригоден для BIM-автоматизации и не требует превращать узлы в монолитные GDL/Morph-объекты;
- Archicad 29 нативно предоставляет достаточную семантику для большинства host-элементов и отношений;
- upstream Tapir значительно шире текущего safe-applier проекта;
- главная инженерная задача расширения — безопасное оркестрирование и верификация операций;
- общая картинка узла без material-specific pack недостаточна.

### Не разрешено для автоматической генерации на этом этапе

- окончательный фундамент любого типа;
- конкретные размеры несущих соединений;
- армирование/анкеровка/опирание;
- точный состав тепловой оболочки без расчета;
- конкретные крепежи окон без основания/изделия;
- размеры проходок без инженерного проекта и КР;
- перенос узлов между masonry/AAC/timber системами;
- использование неподтвержденной команды Tapir для Complex Profiles/Detail/Worksheet.

## Следующий цикл

Материал-специфические packs, начиная с наиболее типичной тяжелой схемы:

1. `masonry + reinforced concrete`;
2. `AAC + reinforced concrete`;
3. `timber frame / timber structures`.

Для каждого pack: фундамент–стена, стена–перекрытие, проем, карниз/кровля, мокрая зона, проходка; затем Archicad recipe и Tapir typed-command contract.
