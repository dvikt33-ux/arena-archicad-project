# Обратный канал (тест, без live)

ChatGPT не получает секрет. HMAC в конверт не кладётся: иначе секрет пришлось
бы отдать модели. Транспорт и проверка доверия разделены.

## Кто чему доверяет

| Что | Доверие |
|---|---|
| Публичный Issue #1 | Только результаты, которые и раньше публиковались. Команды оттуда не читаются. |
| JSON задания | Не доверен. Поле `author` внутри файла игнорируется, лишнее поле отвергается. |
| Приватный mailbox-репозиторий | Только транспорт. Bridge сам спрашивает GitHub API, кто сделал коммит. |
| Коммит | Выполняется только если `author.login` = `dvikt33-ux`, репозиторий private, и committer — вы или `web-flow`. |
| Action | Только `GIT_VERSION`, `GIT_STATUS`, `GIT_LOG10`, `GIT_DIFF`. Аргументов нет. |
| Qwen | По-прежнему недоверен. Секреты и mailbox.json ему не передаются. |

Обычные действия из этого списка не критические: после проверки они
выполняются сами, без `Read-Host` и без кнопки в PowerShell. Действие с
`Critical = $true` (сейчас таких нет) не выполняется. Его можно выпустить
только локальным файлом `approve\<task_id>` с текстом, равным этому `task_id`.
Это не запрос на каждое действие.

## Что выключено по умолчанию

Живой опрос GitHub **выключен**, пока на Windows нет локального файла
`%LOCALAPPDATA%\ArenaBridge\mailbox.json`. Этого файла в git нет и быть не
должно. Пример, который ничего не включает:

```json
{"enabled": false, "repo": "dvikt33-ux/arena-bridge-mailbox", "owner": "dvikt33-ux", "poll_sec": 15}
```

`enabled: true` имеет смысл только после отдельного решения включить реальный
mailbox. Этот этап его не включает и репозиторий не создаёт.

Репозиторий mailbox не может быть `dvikt33-ux/arena-archicad-project`.
Владелец доверия зашит: `dvikt33-ux`. Токенов, HMAC-секретов и PAT в
репозитории нет.

## Формат задания

Один файл `inbox/<seq>.json`. Неизвестное поле, неизвестный action, непустые
`args`, просрочка, старый `seq`, повторный `task_id` — файл не выполняется и
не публикуется в Issue.

```json
{"schema":1,"seq":13,"task_id":"aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee","action":"GIT_STATUS","args":{},"created_at":"2026-09-22T18:00:00Z","expires_at":"2026-09-22T20:00:00Z"}
```

`seq` продолжает `last_seq` Bridge v2, а не начинается заново. Один `task_id`
выполняется не больше одного раза. `RUNNING` после сбоя не перезапускается.
Повторная отправка результата идёт через уже исправленный outbox (PATCH), без
повторного git.

Если GitHub недоступен, Bridge не крутит цикл запросов: следующий опрос не
раньше чем через 5–60 секунд, локальная очередь при этом жива.

## Producer

`arena-mailbox-put.ps1 -Action GIT_STATUS -DryRun` только пишет конверт.
`-Push` ходит в GitHub уже существующим `gh` на Windows и отказывается писать
в публичный проект. Скрипт не принимает текст команды.

Пока mailbox не создан, ChatGPT в браузере сам положить файл не может: для
этого нужен одноразовый fine-grained PAT только на приватный mailbox, и он
должен жить вне этого git и вне чата. Этот этап такой токен не создаёт.
