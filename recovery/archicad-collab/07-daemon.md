# Демон ACCOLLAB v0.2.0 — единая система (руководство оператора)

Демон связывает всё в один цикл: watcher → outbox → транспорт (файлы/relay) →
применение → локи → чекпоинты → status.json. Только stdlib, без установки
зависимостей: `cd src && python -m accollab.daemon ...`.

## Быстрый старт

```
cd src
python -m accollab.daemon --config ../run-a/accollab.json init --author anna
python -m accollab.daemon --config ../run-a/accollab.json once    # один тик
python -m accollab.daemon --config ../run-a/accollab.json run     # цикл
python -m accollab.daemon --config ../run-a/accollab.json status  # status.json
```

## Конфиг (accollab.json)

| Поле | Смысл |
|---|---|
| project_id | общий ID проекта на всех машинах («tropa») |
| author | имя этой машины/участника |
| store | путь к SQLite-журналу |
| poll_s | пауза между тиками в run |
| outbox_dir / inbox_dir | папки файлового транспорта |
| relay_url / relay_secret | ретранслятор (пусто = только файлы) |
| telegram_bot_token / telegram_chat_id | канал-транспорт (пусто = выкл) |
| telegram_secret | HMAC-подпись партий (пусто = без проверки; для команды задать!) |
| archicad_timeout | таймаут долгих команд Archicad |
| archicad_port | пин порта (0 = автоскан 19723–19727; при зомби/нескольких инстансах задать явно) |

## Транспорты

- **Файлы (офлайн):** каждый тик outbox пишется в `outbox/ops-*.json`,
  inbox (`inbox/*.json`) забирается в журнал. Обработанные → `.done.json`,
  чужие протоколы → `.bad.json` (тик не падает). Носитель любой.
- **Ретранслятор (интернет):** если задан relay_url — push/fetch каждый тик,
  курсор хранится в sync_state. Файлы при этом тоже пишутся (аудит),
  очередь гасит relay. Дубли через оба канала безопасны (идемпотентность).
- **Telegram (интернет без сервера):** если заданы telegram_bot_token и
  telegram_chat_id — push/fetch через приватный канал каждый тик (куски
  до 3500 символов, курсор update_id, недособранное в telegram_pending.json,
  429 с retry_after переживается). Настройка: BotFather → токен, приватный
  канал с ботом-админом, chat_id в конфиг. Свой сервер не нужен вообще.
  Командный режим: партии подписываются (telegram_secret), fetch тянет
  всплески страницами, оборванное протухает, порядок применения у всех
  одинаковый, правки под чужим hard-блоком подсвечиваются в warnings.
- **Сервер ретранслятора:** `python -m accollab.relay --port 8471
  --secret ОБЩИЙ-СЕКРЕТ --data relay.jsonl`. Ставится на любую машину,
  доступную обеим сторонам (VPS/офисный сервер/машина A с пробросом порта).
  Сервер тупой: лог по project_id, дедуп по change_id, секрет — общий заголовок.

## Блокировки

- `lock <guid> --mode soft|hard --ttl 20` — занять (soft по умолчанию).
  Lock-операция рассылается соседям через общий транспорт.
- Демон каждый тик продлевает (heartbeat) свои локи; упавший демон =
  блоки протухают через ttl, элемент освобождается сам.
- Hard-блок чужого holder'а запрещает применение его операций на элемент:
  applier отвечает CONFLICT-locked и пишет строку в журнал конфликтов.
- `unlock <guid>`, `locks` — снять/посмотреть.

## Чекпоинты и откат

- `checkpoint <имя> --desc ...` — именованный снимок (хранится в журнале).
- `rollback <checkpoint_id>` — показать план (проект НЕ тронут).
- `rollback <checkpoint_id> --yes` — применить компенсирующие modify-операции
  через штатный applier (с base check и записью в журнал).
- Что нельзя компенсировать (создано/удалено после чекпоинта, изменения без
  координат) — попадает в skipped с причиной, а не ломает откат.

## Конфликты

Любой отказ applier'а (нет элемента / base не совпал / hard-блок) пишет строку
в `conflicts` (open + code). `conflicts` — список, `resolve <id> <текст>` —
закрыть решением пользователя. Авто-разрешение запрещено архитектурой.

## Комментарии

- `comment <guid> <текст...>` — добавить; `comments [guid]` — список;
  `comment-reply <id> <текст>` — ответить; `comment-resolve <id>` — закрыть.
- Расходятся операциями kind=comment через общий транспорт (файлы/relay/Telegram),
  дубли и повторы безопасны.

## Присутствие

Каждый тик демон подсвечивает занятые элементы цветами holder'ов — только
временная подсветка, проект не меняется. Обновление лишь при изменении набора
локов (лишних вызовов в Archicad нет). Цвета — из таблицы participants.

## Бэкап

- `backup --dir <каталог> --keep 5` (или backup_dir в конфиге): копия PLN →
  сверка хэша → ротация. Каталог внутри Яндекс Диска = копии сами в облаке.
- `history <guid>` — последние операции по элементу из журнала.

## Страница статуса (кнопка «Синхронизировать»)

- `serve --port 8472` → открыть http://127.0.0.1:8472 (только этот компьютер).
- Кнопка тика (идёт в фоне, повторный клик не плодит тики). Настраиваемая
  панель: вкладки Статус (карточки), Блоки, Конфликты (закрытие), Чекпоинты
  (+ создание) прячутся в меню «⋯» и возвращаются («⋯ в меню» / «📌 на
  панель» в заголовке); раскладка — ui.json рядом с конфигом. Настройки —
  только колесико ⚙. Сообщения — полосой над вкладками. Русский, без
  внешних ресурсов.
- «Показать» — зум к элементу на экране Archicad (FitInWindow + янтарная
  подсветка); «В Archicad» — диалог выбора по конфликту прямо в Archicad
  (ShowAlert «Моё/Чужое/Позже», выбор пишется в журнал). CLI: `show GUID`.
- «Настройки» — полный пульт accollab.json, 7 групп: Проект; Пути
  (store/outbox/inbox); Демон и Archicad (опрос, пин порта, таймауты, порт
  страницы); Relay (URL + таймаут); Telegram (чат, API, таймаут); Бэкапы;
  Поведение (ttl лока, правила BIM, свой цвет) + галки (подсветка,
  авто-чекпоинт перед чужими, уведомления о конфликтах) + секреты
  (пусто = не менять). Числа валидируются, мусор отвергается с замечанием.
  Пути/порты — после перезапуска, галки — со следующего тика.
  Записи выделения в Tapir нет — показать = зум + подсветка (проверено
  по спеке, 250 команд: evidence/tapir-commands.txt).

## BIM-контроль

- `bim-check` — дубли/пустые ID + отсутствующие материалы по живому снимку
  (советует, не блокирует; exit 3, если есть замечания). Правила по именам
  слоёв — после живого зондажа: команда называется GetLayers (не
  GetLayerAttributes — такого имени в спеке Tapir нет), вход — attributeIds,
  связка layerIndex→атрибут живьём не подтверждена.

## status.json (каждый тик)

Порт Archicad, pending outbox, открытые конфликты, активные локи,
курсор relay, последние 5 ошибок. Это же — будущий источник для кнопки
«Синхронизировать» и индикатора в UI.

## Что уже покрыто тестами (72 шт.)

Watcher→Store→Transfer→Applier, локи (аренда/heartbeat/протухание/remote),
чекпоинты (откат + 3 skipped-ветки), relay (push/fetch/дедуп/секрет/файл),
демон (файловый цикл A→B, hard-блок+конфликт, битый протокол, relay-поток,
telegram-поток, детерминированный победитель, warnings, CLI comments/backup),
telegram (roundtrip, куски, курсор, 429, чужой токен, 4 писателя, prune, подписи),
комментарии (локально/remote/applier/плохие входы), присутствие (группы/тишина/цвета),
бэкап (копия/ротация/чужие файлы/ошибки), BIM (дубли/пустые/чисто),
страница (GET/sync/resolve/checkpoint/show/ask/settings),
коннектор (зум/диалог через мок).

Запуск: `cd tests && python -m unittest test_connector test_watcher test_sync
test_locks test_checkpoints test_relay test_daemon test_telegram test_comments
test_presence test_backup test_bim test_statuspage`

## Что НЕ входит в 0.2.0 (следующие шаги)

Подпись релизов, расширенные BIM-правила (имена слоёв/перья — после живого
зондажа GetLayers), P2P без ретранслятора (NAT запрещает — relay/Telegram
остаются), встроенная палитра в окне Archicad (требует C++ Add-On, этап
DevKit; макет: evidence/palette-mockup.html).
Готово: комментарии, присутствие, пакет EXE/MSI, BIM-база, страница статуса,
экран Archicad (зум/диалоги/настройки),
фоновый /sync.

## Где держать relay бесплатно (проверено 2026-09-12)

- Тест на день: Cloudflare Quick Tunnel на машине A (`cloudflared tunnel --url
  http://127.0.0.1:8471`) — без аккаунта, URL выдать машине B. Эфемерный, для
  постоянной работы не годится.
- Постоянно, просто: Tailscale Personal (free: 6 юзеров, устройства без лимита) +
  relay на одной из машин. Нужен админ на установку клиента в Windows.
- Постоянно, без установок: Supabase free (без карты, 500 МБ, 5 ГБ/мес) +
  будущий транспорт PostgREST в демоне. Пауза после 7 дней тишины (ручное
  пробуждение; рабочий опрос держит проект живым).
- Свой сервер: Oracle Always Free (2 ARM CPU/12 ГБ + 200 ГБ + 10 ТБ/мес) —
  нужна карта и Linux-навыки; provisioning часто «нет мест».
- Без сервера вообще: Telegram-транспорт (бот шлёт ops.json в приватный чат,
  демон забирает через Bot API) — в планах, лимитов хватит на 6 человек.
- ngrok free для демона НЕ годится (сессии 2 часа, 1 ГБ/мес, страница-предупреждение).
- Render free спит после 15 мин тишины и не имеет персистентного диска
  (relay.jsonl потеряется при рестарте) — только как времянка.
