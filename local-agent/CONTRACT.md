# Phase 1 — контракт Local Agent

Дата: 2026-09-23.  
Основа: `bridge-v2/LOCAL_AGENT.md`, аудит `bridge-v2/LOCAL_AGENT_AUDIT.md`.  
Ветка: `arena/local-agent-v0`. `main` этим контрактом не меняется.  
Живой mailbox не включается. `mailbox.json` в git не появляется.

Это контракт, не разрешение. Срез в `local-agent/src` его исполняет только из тестового драйвера внутри процесса. Пока второй агент не проверил diff и platform acceptance test не прошёл, срез не принят. Зелёный прогон здесь не является принятием.

## 1. Чего нет

Следующие возможности отсутствуют. Они не «выключены флагом» и не объявляются в handshake:

- `ui.control`
- `archicad.write`
- `system.admin`
- `package.user_install`
- `workspace.exec`
- `mailbox.poll`
- `issue.publish`
- `git.commit`
- `git.push`
- listener, named pipe, сокет, UI

Нет опроса GitHub, нет чтения и записи `state.json` Bridge, нет публикации в Issue. Репозиторий `arena-archicad-project` не регистрируется как writable workspace. Agent не коммитит и не пушит репозиторий проекта. Вывод модели — данные, не action. Agent обязан работать без локальной LLM. Удалённый authorizer для записи и исполнения — отказ. Криптография не изображается.

## 2. Идентификаторы

| Поле | Роль |
|---|---|
| `step_id` | Ключ идемпотентности. Повтор возвращает сохранённый результат и не исполняется. Новый `step_id` — новый шаг, даже если действие похоже. |
| `request_id` | Транспорт. Не запрещает второе исполнение другого `step_id`. |
| `job_id` | Группа шагов. Не заменяет `step_id`. |

Все три — UUID в нижнем регистре. В одном вызове шаги с разным `job_id` не исполняются (`job-mismatch`). Несовпадение `job_deadline` внутри одного job — `bad-deadline`, без исполнения и без молчаливого продления.

## 3. Конверт

Ровно `schema` = 1 и поля `job_id`, `request_id`, `step_id`, `action`, `args`, `depends_on`, `expires_at`, `job_deadline`. Неизвестное поле на любом уровне — отказ `unknown-field`. Поле не становится командой.

`expires_at` и `job_deadline` — UTC. Срок шага позже срока job — `bad-deadline`. Истёкший шаг или job не исполняется и не ждёт (`expired`).

`depends_on` — массив `step_id` того же job. Цикл, включая зависимость от себя, — `dependency-cycle`. Отсутствующая зависимость — `missing-dependency`. Зависимость не в `COMPLETED` — `dependency-not-satisfied`. Вечного ожидания нет.

## 4. Действия среза

Только эти имена, и только после явного разрешения тестового authorizer:

| Action | Args |
|---|---|
| `FILE_READ` | `path` |
| `FILE_HASH` | `path` |
| `FILE_WRITE_ATOMIC` | `path`, `content_utf8`, необязательный `expected_sha256` |
| `FILE_APPLY_PATCH` | `path`, `expected_sha256`, `patch_utf8` |
| `PROFILE_RUN` | пустой объект |

Любое другое имя, включая `GIT_COMMIT`, `GIT_PUSH` и текст shell, — `unknown-action`. Аргумент не из таблицы — `unknown-field`. Произвольный argv из задачи отвергается: `PROFILE_RUN` не принимает аргументы.

`FILE_READ` возвращает в результате точный UTF-8 текст файла. BOM не отрезается, переводы строк не нормализуются. Предел `1048576` байт: чтение останавливается на пределе и не сохраняет хвост. Больше предела — `read-limit`, `FAILED`, Output пустой. Байты не являются UTF-8 — `bad-encoding`, `FAILED`, Output пустой. `FILE_HASH` считает hash и не возвращает тело.

`FILE_WRITE_ATOMIC`: нет файла и нет `expected_sha256` — создание через exclusive create. Файл уже есть, а hash не передан — `conflict-exists`, без перезаписи. Hash не совпал — `conflict-hash`, без перезаписи. Файла нет, а hash передан — `conflict-hash`, это не создание. После replace — flush и read-back. Кодировка, BOM и LF/CRLF входят в hash и не нормализуются. Несовпадение read-back — `NEEDS_REVIEW`, не успех. `expected_sha256` вместе с replace не является межпроцессным compare-and-swap и допустим только во временном тестовом workspace этого среза.

`FILE_APPLY_PATCH` не создаёт файл и не берёт путь из текста патча. Первая строка патча ровно `ARENA-PATCH/1`. Дальше блоки `@@` и строки ` `, `-`, `+`. Заголовки `diff`, `---` и `+++` запрещены. Несовпадение контекста — `patch-mismatch`, файл не меняется. Байты цели, которые не являются строгим UTF-8, — `bad-encoding`, `FAILED`, файл не пишется и исходные байты сохраняются.

## 5. Путь

Путь относительный, внутри временного workspace. Отказ `path-escape` для абсолютного пути, диска, UNC, `..`, `.`, пустого сегмента, `:`, ADS, имён устройств (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`), `* ? " < > |`, хвостовых точки и пробела. Существующий reparse point на компоненте пути не обходится. Reparse point на самом workspace, каталоге данных или любом их предке — `workspace-forbidden`: junction и symlink в предке не становятся путём в запрещённое дерево. Промежуточный компонент, который является обычным файлом, — `path-not-directory`, без записи. Ожидаемые `IOException` и `UnauthorizedAccessException`, включая sharing violation, не выходят из `Run`: терминальный результат `io-failed` либо более точный отказ пути. Workspace не может быть репозиторием проекта, каталогом с `.git`, каталогом agent/policy или каталогом данных agent.

## 6. Authorizer

`IAuthorizer` есть. `RemoteAuthorizer` всегда возвращает `remote-deny` и ничего не исполняет. `TestAuthorizer` разрешает только явно переданный `step_id` и только действие из таблицы среза. Разрешение репозитория, автор коммита и текст модели сюда не входят.

## 7. Состояния и сбой

Терминальные отказы: `REJECTED`, `CONFLICT`, `FAILED`, `NEEDS_REVIEW`. Успех: `COMPLETED`. Перед записью файла или запуском профиля устойчиво пишется `RUNNING`.

Повтор того же `step_id` возвращает сохранённую запись. Новое тело, другой action и битый повторный конверт исполнение не заменяют. Два новых конверта с одним `step_id` в одном вызове дают одно исполнение: канонический — первый, второй возвращает сохранённый результат. Перед записью файла и перед запуском профиля `step_id` атомарно занимается (`INSERT` при конфликте не перезаписывает). Проигравший вызов не исполняется. Для уже сохранённого `step_id` согласованность вызова берёт канонические `job_id` и `job_deadline` из записи, а не из тела повтора. Обновление записи не заменяет эти поля. Если сохранённый срок нельзя проверить, новый шаг не исполняется (`bad-deadline`). Для ещё не сохранённого шага берутся поля его конверта. Несогласованный вызов новый шаг не исполняет.

Восстановление `RUNNING` не исполняет шаг снова. Если файл уже совпал с записанным intended hash, состояние становится `COMPLETED` без второй записи. Если не совпал, или hash не предусмотрен, — `NEEDS_REVIEW` без слепой записи и без повторного запуска профиля.

## 8. Профиль и процесс

Один именованный профиль `test-profile`. Он лежит вне writable workspace. Файл профиля внутри этого workspace, в том числе через reparse alias в него, — `profile-mismatch` до загрузки и до запуска процесса. Agent сверяет hash файла профиля и hash executable. Несовпадение — `profile-mismatch`, процесс не запускается. Job не может сменить профиль.

Дочерний процесс не наследует окружение. Секреты авторизации и GitHub token в него не копируются. Ненулевой код выхода — `FAILED` и `exit-code`, не успех. Stdout и stderr читаются с байтовым пределом; превышение убивает управляемого ребёнка (`stdout-limit`). Timeout убивает только процесс, который agent сам запустил, и только если совпали pid, executable и start time. Чужой процесс не в списке. Полный сетевой запрет Windows этим срезом не обещается: сокет не открывается, но sandbox сети не объявляется.

## 9. Модель

Интерфейс advisory. Ответ не выбирает action, путь и hash. Нет локальной LLM — шаг всё равно исполняется по конверту. Timeout модели не становится командой. Срез не открывает endpoint.

## 10. Хранилище

Состояние среза — SQLite в каталоге данных agent. `journal_mode=WAL`, `synchronous=FULL`. Bridge на SQLite не переводится. Общей очереди нет.

## 11. Проверка

Поведенческий критерий среза: `dotnet test` два чистых прогона. Проверка фраз контракта — `local-agent/tests/contract-checks.ps1`. Она не исполняет шаги и не заменяет `dotnet test`. Windows platform acceptance этого среза этим файлом не утверждается.
