## 1. Проверка реализуемости (честно, по источникам)

### Что реально умеет официальный JSON API Archicad (встроенный, порт 19723+)

- Получение элементов: GetAllElements, GetElementsByType, GetDetailsOfElements, GetPropertyValuesOfElements, GetClassificationOfElements. [1](https://github.com/SzamosiMate/multiconn_archicad)
- Ограниченное создание/изменение: создание стен/плит/колонн/объектов через официальные команды; установка значений свойств.
- Подключение нескольких открытых инстансов Archicad по портам (multiconn-подход). [2](https://github.com/SzamosiMate/multiconn_archicad)
- ❌ Нет push-событий. Только polling (запрос → ответ). Нет подписки «сообщи, когда пользователь начал редактировать стену».
- ❌ Нет перехвата начала/конца редактирования в UI, нет запрета редактирования чужого элемента.
- ❌ Нет встроенного журнала изменений, версий, undo-группировки для внешних клиентов.

### Что добавляет Tapir Add-On (community, ENZYME-APD, ~191+ команд вместе с официальными)

- HighlightElements — временная подсветка элементов цветом без изменения перьев/материалов (идеально для цветов участников). [3](https://github.com/SzamosiMate/multiconn_archicad)
- Расширенные команды: MoveElements, CreateSlabs/Columns/Objects, GetGDLParameters/ChangeGDLParameters, GetHotlinks, TeamworkReceive, GetProjectInfo и др. [4](https://github.com/tlorantfy/archicad-additional-json-commands)
- Документация команд доступна без запущенного Archicad (через MCP-обёртки, подтверждающие зрелость схем). [5](https://github.com/Boti-Ormandi/archicad-mcp)
- ❌ Всё равно request/response по HTTP на localhost. Реального времени «из коробки» нет — нужен Watcher с опросом + diff.
- ❌ Не может жёстко заблокировать элемент от редактирования пользователем в Archicad. Только кооперативная (soft) блокировка + визуальное предупреждение.
- ⚠️ Tapir нужно устанавливать и обновлять отдельно на каждой машине, версия должна совпадать со схемой команд.

### Что умеет только C++ Add-On API (DevKit 29)

- Подписка на события элементов: ACAPI_Element_InstallElementObserver + ACAPI_Element_AttachObserver, ACAPI_Element_CatchNewElement — уведомления о создании/изменении/удалении наблюдаемых элементов. [6](https://graphisoft.github.io/archicad-api-devkit/group___element.html)
- Отслеживание undo/серий событий между APINotifyElement_BeginEvents / EndEvents. [7](https://community.graphisoft.com/t5/Archicad-C-API/Monitor-undos/td-p/693278)
- Проверка редактируемости: ACAPI_Element_Filter(elemGuid, APIFilt_IsEditable); блокировка Edit/Lock через ACAPI_Element_Tool; проверка слоя (APILay_Locked) и hotlink (hotlinkGuid). [8](https://community.graphisoft.com/t5/Archicad-C-API/Locked-Element/td-p/260163)
- Teamwork-резервирование: ACAPI_Teamwork_ReserveElements / ReleaseElements, статусы lockable-объектов, уведомления CatchElementReservationChange. [9](https://graphisoft.github.io/archicad-api-devkit/group___teamwork.html)
- Полная геометрия, включая Morph (API_ElemInfo3D, API_Component3D, ACAPI_Body_Create). Через JSON геометрия Morph почти недоступна.
- ⚠️ Требует отдельной сборки под каждую версию Archicad и платформу (Win/Mac), подписи, установки, поддержки. Разработка дольше в 3–5 раз, чем Tapir-прототип.
- ⚠️ Изменение материала/атрибута, уже назначенного элементам, НЕ ловится ElementObserver'ом напрямую — нужен обход через Project Notification (APINotify_TempSave) + сравнение атрибутов. [10](https://community.graphisoft.com/t5/Archicad-C-API/Can-t-get-material-change/td-p/339870)

### Teamwork API — важное ограничение

- Работает ТОЛЬКО в Teamwork-проектах (BIMcloud/BIM Server). В обычном solo PLN функции резервирования неприменимы. Наш модуль строится для solo PLN + P2P, поэтому Teamwork API — не основа, а опциональная интеграция (если проект уже Teamwork — не мешаем, читаем статусы).
- Конфликт резервирований в Teamwork — штатная ситуация, решается через Request/Release All/Force Leave. [11](https://support.graphisoft.com/hc/en-us/articles/26450125390865-Can-t-reserve-objects-in-Teamwork-Object-conflict-error) Наш модуль должен давать аналогичный UX для soft-локов.

## 2. Ограничения Archicad 29 (зафиксировать до разработки)

1. Нет server-push из Archicad наружу. Любой «реалтайм» через JSON = polling. Задержка детекта 1–3 с в прототипе — норма.
2. Нет API «запретить редактирование конкретного элемента для этого пользователя, но показать его». Есть: Edit/Lock (глобально), Layer Lock (по слою), Teamwork Reserve (только Teamwork). Кооперативный лок — наш уровень, не уровень Archicad.
3. GUID стабилен, но при undo/copy/hotlink-разрыве/конвертации может появиться новый GUID. Нужны tombstones и карта переименований.
4. Операции извне попадают в undo-стек Archicad. Нужна группировка (начать группу → применить пакет → закрыть) и маркировка «применено из Sync», иначе пользователь случайно откатит чужое изменение.
5. Массовые операции: JSON применяет поэлементно, медленно на 10k+ элементов. Нужны батчи, прогресс, отмена, ночной режим для больших применений.
6. Morph/Mesh/лестницы/ограждения: через JSON — почти только чтение оболочки. Полноценный diff/apply — только C++.
7. Атрибуты: создание дублей легко, запретить сложно. Контроль стандартов в v1 — детектор + предупреждение + журнал, а не блокиратор.
8. Два инстанса Archicad на одной машине = два порта. Демон должен привязываться к конкретному проекту (ProjectID = hash(ProjectInfo + путь + GUID первого запуска), а не к порту).
9. Сохранение PLN: автосохранение триггерить осторожно; перед массовым применением — предлагать сохранить и делать локальный бэкап.
10. Производительность: полный GetDetails по всем элементам большого проекта — секунды/десятки секунд. Нужны инкрементальные хэши, кэш, лимиты polling (активный вид/этаж в приоритете).

## 3. Предлагаемая архитектура

```
┌─ Рабочее место A ─────────────────────────────────┐  ┌─ Рабочее место B ──────┐
│ Archicad 29 (solo PLN) + Tapir Add-On             │  │ Archicad 29 + Tapir    │
│        ▲ localhost HTTP (19723+)                  │  │        ▲               │
│ Collab Daemon (Python, позже Rust-ядро опционально)│  │ Collab Daemon          │
│ ┌──────────┐ ┌───────┐ ┌────────┐ ┌─────┐ ┌─────┐ │  │ (такой же состав)      │
│ │Connector │ │Watcher│ │ Store  │ │Sync │ │ UI  │ │◄─┼─► P2P TLS (mDNS LAN,  │
│ │(Tapir)   │ │(poll/ │ │(SQLite│ │Eng. │ │(web │ │  │   прямое/relay для WAN)│
│ │          │ │ diff) │ │ +WAL) │ │     │ │пан.)│ │  │                        │
│ └──────────┘ └───────┘ └────────┘ └─────┘ └─────┘ │  │                        │
└──────────────────────────────────────────────────┘  └────────────────────────┘
                              │ опционально
                     Yandex Disk Backup Worker (только бэкапы, verify-then-rotate)
```

**Компоненты демона (один процесс, модули):**

- **Connector** — клиент Tapir/official JSON: чтение элементов/свойств, применение операций, HighlightElements, выбор/переход к элементу.
- **Watcher** — цикл опроса: снимок → хэш → diff → первичная операция. Эвристика «редактируется сейчас»: элемент в текущей выборке + меняется между тиками + фокус Archicad. Точный старт/конец редактирования — только с C++ Add-On (2-я очередь).
- **Store** — SQLite (WAL): oplog, кэш элементов, локи, комментарии, чекпоинты, outbox, sync_state. Подпись операций Ed25519, хэш SHA-256.
- **Sync Engine** — P2P: discovery (mDNS в LAN), handshake (project key из invite-кода/QR), обмен векторами версий → gossip недостающих операций → ack → apply. Идемпотентность по change_id, повторная отправка безопасна.
- **Lock Manager** — lease-локи: heartbeat 5 с, timeout 20 с, автоосвобождение, журнал. Soft в v1, hard через C++ позже.
- **UI** — локальная веб-панель (открывается рядом с Archicad, не внутри него в v1): участники, статус, очередь, конфликты, история, комментарии, кнопки [ВЕСЬ ПРОЕКТ / МОЯ ЧАСТЬ], [Подсветка изменений], [🔄 СИНХРОНИЗИРОВАТЬ]. Встройка палитры внутрь Archicad — только через C++ (2-я очередь).

**Почему демон, а не «всё внутри Archicad»:** Archicad не умеет P2P, SQLite-журнал, фоновую синхронизацию и веб-панели из коробки. Демон — единственный честный путь для v1 без ожидания C++ разработки.

## 4. Список компонентов (v1 и позже)

**v1 (прототип, Tapir-only):** Connector, Watcher(poll), Store(SQLite), Sync(LAN mDNS + TLS PSK), Locks(soft), UI(web), Backup(ручной экспорт zip + manifest).
**v2:** C++ Observer Add-On (точные события, hard-lock, Morph-геометрия), WAN-транспорт (relay/Tailscale-инструкция), комментарии с привязкой к субэлементам, контроль стандартов v2.
**v3:** центральный опциональный сервер (история/поиск/админка), установщик, автообновление, мониторинг производительности.

## 5. Схема обмена (операционный журнал, gossip)

1. A меняет стену → Watcher фиксирует diff → создаёт op (change_id UUIDv7, base_vector, tx_id).
2. Op подписывается ключом A, кладётся в SQLite + outbox.
3. При наличии связи: A → B: `HELLO(vector)`, B → A: `NEED(ids)`, A → B: `OPS(batch)`, B → A: `ACK(ids)`.
4. B проверяет подпись, зависимости, лок чужого элемента → применяет через Tapir → пишет в свой oplog как applied-remote.
5. Офлайн: op ждёт в outbox; при reconnect — та же процедура + отчёт + конфликты.
6. Конфликт (один GUID, пересекающиеся base): обе версии сохраняются, создаётся Conflict, в UI сравнение до/после, выбор пользователя, решение — новой операцией resolution (тоже в журнале).

Векторные часы: `version_vector = {participant_id: seq}`. Lamport time для сортировки при равных условиях. Часы wall-clock только для отображения, решения — по векторам + хэшам (защита от рассинхронизации времени).

## 7. План разработки (этапы, без смешивания с AI/BIBIM/MCP)

- **Этап 1 — Исследование (этот документ).** Выход: подтверждённые возможности/ограничения, архитектура, схемы. Критерий: пользователь выбрал путь A (Tapir-only) или B (Tapir+C++).
- **Этап 2 — Скелет демона + Store + Connector.** Подключение к 2 Archicad, ProjectID, GetAllElements/GUID, локальный oplog, веб-панель статуса.
- **Этап 3 — Watcher + одна операция end-to-end.** Poll → diff → op → outbox → ручной экспорт/импорт файла → apply на второй машине → подсветка.
- **Этап 4 — P2P LAN + локи + кнопка синхронизации.** mDNS, TLS PSK, gossip, soft-lock с heartbeat, индикатор очереди.
- **Этап 5 — Конфликты + история + восстановление + чекпоинты.** UI сравнения, resolution-операции, Time Machine через компенсирующие op'ы.
- **Этап 6 — Комментарии + режимы просмотра + стандарты-детектор.** Привязка к GUID/точке, фильтры, детектор дублей атрибутов.
- **Этап 7 — Закаливание:** тесты по разделу 21 ТЗ, бэкап Yandex Disk (verify-then-rotate), диагностика perf, доки, установщик.

## 8. Риски (главные)

1. Polling-задержка и ложные «редактируется» → смягчение: adaptive интервал, хэши, C++ во v2.
2. GUID-пересоздание при undo/copy → tombstones + карта + эвристика сопоставления по checksum+тип+позиция.
3. Undo-стек: пользователь откатит чужое → группировка + префикс в имени undo + обучение + опция «защитить remote-операции» (C++).
4. Большие проекты: долгий первый снимок → прогресс + постраничность + кэш + «быстрый режим: только активный этаж».
5. WAN без сервера: NAT → в v1 честно LAN + ручной обмен файлами + инструкция по Tailscale/WireGuard; relay — v2.
6. Безопасность: PSK + Ed25519 + TLS; отзыв через ротацию ключа и чёрный список participant_id; без публичных туннелей по умолчанию.
7. Yandex Disk: удаление старой копии только после verify новой (size+sha256+probe-download HEAD).

## 9. Минимальный прототип (что именно покажем первым)

1. Два Archicad с одинаковым стартовым PLN (раздаём вручную).
2. Демон на каждой машине: видит свой Archicad, показывает ProjectID, число элементов, статус.
3. Изменение одной стены на A → op в локальном журнале → файл outbox.json → перенос на B → apply → стена двигается, подсветка цветом A, запись в истории.
4. Soft-lock: A «берёт» элемент → на B пульсация + имя; попытка изменить на B → предупреждение (не жёсткий запрет в v1).
5. Кнопка [🔄 СИНХРОНИЗИРОВАТЬ], счётчик очереди, отчёт.

## 10. Критерии готовности (для каждого этапа)

- Что реализовано / проверено / не проверено — списком.
- Ограничения, обнаруженные тестом (не теорией).
- Файлы, запуск, тест, откат.
- Опасные действия: подтверждение + журнал + отмена (везде, без исключений).
- Ни одна версия при конфликте не удаляется молча (тест: офлайн-правки одного элемента с двух сторон → обе на месте + диалог выбора).

## Приложение: ответы на ключевые разделы ТЗ (кратко)

- **Офлайн:** всё пишется локально, outbox durable; при reconnect — автосинх + отчёт + конфликты; чужое молча не перезаписываем.
- **Режимы просмотра:** «МОЯ ЧАСТЬ» = фильтр/изолят через Highlight + Selection, не удаление данных; «ВЕСЬ ПРОЕКТ» = полный вид + подсветка.
- **Цвета:** только HighlightElements overlay, проект не трогаем; настройка/отключение в один клик.

- **Зависимости:** kind=primary/derived, tx_id на массовые; «что сделал Archicad сам» — derived в том же tx в окне N секунд.
