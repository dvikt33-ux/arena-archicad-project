# Обратный канал (тест, без live)

ChatGPT не получает секрет. HMAC в конверт не кладётся: иначе секрет пришлось
бы отдать модели. Транспорт и проверка доверия разделены.

## Кто чему доверяет

| Что | Доверие |
|---|---|
| Публичный Issue #1 | Только уже разрешённые результаты. Команды оттуда не читаются. `GIT_DIFF` не публикуется. `GIT_STATUS` — краткая сводка, не сырой вывод. |
| JSON задания | Не доверен. Неизвестное поле, в том числе поле автора, не выполняется. |
| Коммит | Не разрешение. Логин автора коммита не решает, выполнять ли задачу. |
| Приватный mailbox | Только транспорт. Выполнение возможно, только если репозиторий private, не форк, имя точное, владелец `dvikt33-ux`, страницы collaborators не содержат лишнего push/admin/maintain, страницы deploy keys пустые. |
| Непрочитанные или неполные права | Отказ. Задача не выполняется. Двадцать полных страниц без конца — тоже отказ. |
| Уже лежащий файл | Текущие права не доказывают, кто его положил. Бывший writer мог оставить задачу. Это не чинится подписью «для вида» и не чинится автором коммита. |
| Action | Только `GIT_VERSION`, `GIT_STATUS`, `GIT_LOG10`, `GIT_DIFF`. Аргументов нет. |

Пагинация collaborators и deploy keys обязательна и не доказывает exclusive
writer. Она не видит GitHub App и installation token с Contents:write, учётные
данные Actions и другие интеграции. Этот остаток приемлем только для четырёх
действий только для чтения. Для `workspace.write`, `workspace.exec`,
`archicad.write`, `ui.control`, установки пакетов и admin та же модель
запрещена.

Обычные действия из этого списка не критические: после проверки они
выполняются сами, без `Read-Host` и без кнопки в PowerShell. Действие с
`Critical = $true` (сейчас таких нет) не выполняется. Его можно выпустить
только локальным файлом `approve\<task_id>` с текстом, равным этому `task_id`.
Это не запрос на каждое действие.

## Что выключено по умолчанию

Живой опрос GitHub **выключен**, пока на Windows нет локального файла
`%LOCALAPPDATA%\ArenaBridge\mailbox.json`. Этого файла в git нет и быть не
должно. Пример, который ничего не включает:

```json
{"enabled": false, "repo": "dvikt33-ux/arena-bridge-mailbox", "owner": "dvikt33-ux", "poll_sec": 15}
```

`enabled: true` имеет смысл только после отдельного решения включить реальный
mailbox. Этот этап его не включает и репозиторий не создаёт.

Репозиторий mailbox не может быть `dvikt33-ux/arena-archicad-project`.
Владелец доверия зашит: `dvikt33-ux`. Токенов, HMAC-секретов и PAT в
репозитории нет.

## Формат задания

Remote-имя — `inbox/<task_id>.json`. Это не слот исполнения. Producer не
занимает локальный seq. Поле `seq` в его конверте — заполнитель схемы, не
номер Bridge. Локальный seq продолжает `last_seq` и выбирается только при
импорте, одной резервацией с роутером.

Старое числовое имя принимается только если оно совпадает с полем `seq`.
Иначе отказ. `mailbox-staging/<task_id>.json` не занимает дыру локальной
очереди. Локальный gap-wait остаётся: нет настоящего `inbox/<n>.json` — ждать.

Уже обработанный remote-файл с тем же sha не скачивается снова и не занимает
окно из 20 новых файлов. Список contents на 1000 имён неполный: это не пустой
inbox. `archive/` не читается и не исполняется. Поле `path` из API
игнорируется.

Удаление remote — best-effort и только после устойчивого disposition. Для
принятой задачи — только после записи локального inbox. Ошибка удаления не
повторяет исполнение. Повтор того же `task_id` второй слот не создаёт.
`held` без локального approve не удаляется и не считается закрытым.

После durable `accepted` срок transport-envelope больше не отменяет задачу.
Принятый конверт сохраняется локально в `mailbox-accepted/<task_id>.json`.
Если remote-файл потом изменился, выполняется сохранённый конверт, а не новая
версия. Сбой после резервации слота, но до записи `exec_seq`, при рестарте
забирает ту же живую резервацию, а не открывает следующий номер.

```json
{"schema":1,"seq":1,"task_id":"aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee","action":"GIT_STATUS","args":{},"created_at":"2026-09-22T18:00:00Z","expires_at":"2026-09-22T20:00:00Z"}
```

Один `task_id` выполняется не больше одного раза. `RUNNING` после сбоя не
перезапускается. Повторная отправка результата идёт через уже исправленный
outbox (PATCH), без повторного git.

Если GitHub недоступен, Bridge не крутит цикл запросов: следующий опрос не
раньше чем через 5–60 секунд, локальная очередь при этом жива.

## Producer

`arena-mailbox-put.ps1 -Action GIT_STATUS -DryRun` пишет
`mailbox-staging/<task_id>.json`. `-Seq`, если его передали, игнорируется.
`-Push` ходит в GitHub уже существующим `gh` на Windows и отказывается писать
в публичный проект. URL — `inbox/<task_id>.json`. Скрипт не принимает текст
команды.

Пока mailbox не создан, ChatGPT в браузере сам положить файл не может: для
этого нужен одноразовый fine-grained PAT только на приватный mailbox, и он
должен жить вне этого git и вне чата. Этот этап такой токен не создаёт.

Ограничение явное: скомпрометированный аккаунт владельца всё ещё может
поставить в очередь одно из четырёх действий только для чтения. Подпись не
подделывается, секрет модели не выдаётся. Будущий цикл правок описан в
`AUTONOMY.md`; повышенный helper не реализован. Граница Local Agent —
`LOCAL_AGENT.md`.
