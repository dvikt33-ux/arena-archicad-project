# Normative Base Audit — 2026-09-30

## Verdict

The current committed baseline contains only rules whose document status and stated clause/table were checked during this audit. Values that could not be resolved without project conditions, calculation, manufacturer working drawings, or a current exact clause were **blocked instead of guessed**.

This audit does not certify an entire building design. It certifies the provenance and intended use of the rules currently encoded in `normative-base/`.

## Pass 2 — dimensional semantics audit

The following concepts were separated and are not allowed to overwrite one another:

1. coordination dimension;
2. constructive dimension;
3. product nominal dimension;
4. rough-opening dimension;
5. clear dimension;
6. finish-to-finish dimension.

Critical examples:

- a 6M coordination opening does not automatically mean a manufactured window block of exactly 600 mm;
- a slab coordination length does not automatically equal its constructive/manufactured length;
- a clear room height is not a floor-to-floor coordination height;
- a brick nominal size is not a complete masonry module unless the actual bond/joints/detail are resolved.

**Pass result:** PASS. The base contains explicit anti-substitution guardrails.

## Pass 4 — “typical practice” rejection audit

The following shortcuts were explicitly rejected:

| Shortcut | Audit result | Reason |
|---|---|---|
| `slab_bearing = 120 mm` universally | REJECTED | bearing depends on structural/support/product/project conditions |
| `mortar_joint = 10 mm` universally | REJECTED/PENDING CLAUSE EXTRACTION | common practice is not sufficient evidence for a universal executable rule |
| `mortar_joint = 12 mm` universally | REJECTED/PENDING CLAUSE EXTRACTION | same reason |
| `pier is valid if it is a brick multiple` | REJECTED | modularity does not establish structural capacity/stability |
| `pier is valid if it is 3M or 6M` | REJECTED | ГОСТ 28984 preference is not a masonry capacity check |
| `lintel = function(opening width)` | REJECTED | loads, support/detail and product data are also required |
| `rough opening = window product size` | REJECTED | installation joint/interface must be resolved |
| `all floors = 3000 mm` | REJECTED | coordination and clear-height rules are use/condition dependent |
| `all public rooms = 3000 mm` | REJECTED | СП 118 contains functional/conditional exceptions and redirects |
| `all stairs/doors/corridors use one remembered width` | REJECTED | evacuation/accessibility dimensions depend on exact applicability conditions |
| `insulation thickness = fixed catalogue value` | REJECTED | thermal calculation + current climate/material inputs required |
| `shaft size = standard guessed rectangle` | REJECTED | architecture must reserve from actual engineering assignment/calculation |

**Pass result:** PASS. No rejected shortcut remains encoded as a hard numeric rule.

## Pass 5 — stale cross-reference audit

A current standard may still cite an older standard in its own historical text. Therefore the agent must not treat every cited designation as automatically current in the Russian Federation.

Verified example: the accuracy standards referenced by ГОСТ 28984 are normalized to their current Russian replacements. This pattern must be repeated when adding every new rule pack.

**Pass result:** PASS for the current core pack; repeat per new pack.

## Pass 6 — cross-discipline boundary audit

Architectural geometry was checked for required handoffs:

- load-bearing dimensions -> KR / structural calculation;
- foundations -> geotechnical + structural calculation;
- insulation -> thermal calculation;
- evacuation -> fire classification/occupancy/current fire clauses;
- accessibility -> route/use conditions/current accessibility clauses;
- daylight/insolation -> calculation and sanitary/function conditions;
- acoustic adjacency -> acoustic requirements/calculation where applicable;
- shafts/plenums -> MEP requirements;
- product-specific geometry -> current manufacturer working drawings/catalogue after normative permission.

**Pass result:** PASS. The current core does not claim architectural authority over calculations belonging to another discipline.

## Pass 7 — contradiction / uncertainty audit

### Intentionally not encoded yet

1. Exact current ГОСТ 948-2016 lintel designation/table changes after Amendment No. 1: the general standard status is recorded, but detailed automatic designation selection remains blocked until the amendment text is reconciled against the base standard.
2. Universal masonry mortar-joint thickness: not encoded until the exact current execution clause/tolerance and applicability are extracted.
3. Fire egress dimensions: not yet in the core dimensional pack; they require a dedicated condition-rich pack.
4. Accessibility dimensions: not yet in the core dimensional pack; same reason.
5. Specialized public-building functions (schools, preschool, healthcare, hotels, sports, cinemas, retail, transport): require dedicated SP/sanitary dispatch, not one generalized template.
6. Daylight/insolation, parking/site, roof/floor assemblies and thermal values require dedicated rule packs and/or calculations.

### Audit principle

If two current sources appear to conflict, if a clause cannot be verified in its current wording, or if applicability conditions are missing, the rule state is `BLOCKED_PENDING_AUDIT`; geometry must not be generated from it.

**Pass result:** PASS by fail-closed behavior.
