==============================================================
ACCOLLAB: ЖИВОЙ ТЕСТ — «письма с сервера» в Archicad 29
==============================================================
Дата: 18.09.2026. Время: ~20 минут.

ЧТО ПРОВЕРЯЕМ
-------------
Вы — машина A. С «сервера» (от коллеги boris) последовательно
приходят файлы с изменениями проекта. После каждого файла демон
должен сам применить изменение: элемент в Archicad сдвинется.
Всего 3 письма = 3 сдвига. Конфликтов быть не должно.

ЧТО НУЖНО
---------
1. Windows, Python 3.12+ (проверка: python --version).
   Нет Python — запустите setup.bat из старого кита второй машины,
   он ставит Python сам.
2. Archicad 29 с установленным Tapir (через Add-On Manager).
3. КОПИЯ вашего проекта: Файл → Сохранить как → test-sync.pln.
   Тест ДВИГАЕТ элементы. Оригинал не трогаем!
   В проекте должно быть хотя бы 3 элемента (лучше балки).
4. Этот кит, распакованный в папку БЕЗ русских букв в пути,
   например C:\accollab-test

ШАГ 0. Подготовка
-----------------
- Распакуйте кит в C:\accollab-test
- Откройте КОПИЮ проекта (test-sync.pln) в Archicad 29.
- Откройте командную строку в папке кита: в проводнике кликните
  в адресную строку папки, наберите cmd, нажмите Enter.
- Проверьте Python:  python --version   (нужен 3.12 или новее)

ШАГ 1. Создать конфиг (один раз)
--------------------------------
  daemon.bat init --author ya

Ожидаем: config zapisan: ...accollab.json

ШАГ 2. Создать «письма с сервера» (один раз)
--------------------------------------------
  make-server-files.bat

Скрипт прочитает ВАШ проект и запишет 3 файла в server-files\.
Ожидаем примерно:
  Archicad nayden: port 1972x
  elementov: NN (balok: MM)
  pisem zapisano: 3 -> ...
    server-01.json  <guid>  Beam  dx=0.5
    server-02.json  <guid>  Beam  dx=0.5
    server-03.json  <guid>  Beam  dx=0.5

Запишите, какие GUID в каких письмах (понадобится для сверки).
Если STOP: Archicad ne nayden — см. раздел «Если что-то не так».

ШАГ 3. Базовый тик (снимок «как было»)
--------------------------------------
  daemon.bat once

Команда напечатает большой JSON. Смотрим в нём:
  "baseline": true, "ops": [], "imported": 0, "errors": []
Первый тик только запоминает состояние, ничего не двигает.
Рядом с конфигом появятся папки inbox\ и outbox\.

Во время всего теста используйте только once (по одному тику),
команду run (цикл) не запускайте — шаги должны идти по одному.

ШАГ 4. Письмо 1
---------------
- Скопируйте server-files\server-01.json в папку inbox\
- Выполните:  daemon.bat once
- Смотрим в Archicad: первый элемент из списка сдвинулся на 0.5 по X.

В JSON ищем: "imported": 1,
  "applied": [ { "status": "APPLIED", ... } ], "errors": []

Найти элемент на экране:  daemon.bat show <guid>
(Archicad сам покажет элемент: зум + янтарная подсветка.)

ШАГ 5. Письма 2 и 3 — так же, строго по одному
----------------------------------------------
  копия server-02.json -> inbox, daemon.bat once, смотрим сдвиг;
  копия server-03.json -> inbox, daemon.bat once, смотрим сдвиг.

ВАЖНО: строго по одному файлу и строго по порядку 01 → 02 → 03.
Не двигайте элементы руками между тиками!

ШАГ 6. Проверки
---------------
  daemon.bat status      — сводка (конфликтов 0)
  daemon.bat conflicts   — должен быть пуст
  daemon.bat serve       — страница http://127.0.0.1:8472
                           (кнопка «Синхронизировать», вкладки;
                           остановка — Ctrl+C)

ДОП. ТЕСТ (по желанию): ручная правка
-------------------------------------
Сдвиньте любую балку мышью в Archicad, выполните daemon.bat once:
в JSON в разделе watch появится непустой "ops": [...] — демон увидел
ВАШУ правку и положил её в outbox\ (файл ops-*.json). Это исходящие —
их понесём на сервер.

ЕСЛИ ЧТО-ТО НЕ ТАК
-------------------
- «Archicad ne nayden»: проект точно открыт? Tapir установлен?
  Лишние Archicad закрыты (оставьте один 29)? Раньше бывало «зомби»
  на порту 19723 — лечится перезапуском Archicad.
- «python не является внутренней командой»: Python не в PATH.
  Либо setup.bat из старого кита, либо команда py вместо python
  (тогда и в bat-файлах замените python на py).
- В applied статус "CONFLICT-base": элемент успели поменять руками.
  Так задумано: чужие правки поверх ваших без спроса не накатываются.
  Откат мышиного сдвига: Ctrl+Z в Archicad, затем повторите once.
- В applied статус "ERROR-archicad": Archicad завис или показывает диалог.
  Закройте диалоги, повторите once — порядок не нарушится.
- Любой другой STOP: скопируйте ВЕСЬ вывод команды в Блокнот
  и пришлите мне вместе с файлами (см. ниже).
