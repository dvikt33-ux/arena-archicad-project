# Библиотека нормативных документов

Статус: доказательный и маршрутизирующий слой нормативной базы. Библиотека **не является production-rule engine** и сама по себе не разрешает автоматическое применение числового требования.

## Назначение

Библиотека хранит машинно-читаемые карточки нормативных документов: идентичность документа, официальный источник, редакцию и изменения, область применения, классы объектов, проверенные locator'ы и нерешённые блокеры.

Главная задача — не допускать загрузку нерелевантных норм. Например, профиль ИЖС не должен автоматически подтягивать специальные нормы МКД, производственных или иных классов объектов только потому, что документ присутствует в общей базе.

## Иерархия доказательств

1. `official_clause_verified` — конкретный пункт/таблица/приложение прочитаны непосредственно в официально опубликованном документе.
2. `authorized_locator_verified` — конкретный locator прочитан в авторизованной нормативно-правовой системе и однозначно привязан к действующей редакции.
3. `official_card_verified` — официальная карточка Росстандарта/официального органа подтверждает идентичность, статус, область применения, изменения и даты, но не доказывает текст конкретного пункта.
4. `secondary_corrob_only` — вторичный источник согласуется с ожидаемым текстом, но не является основанием для production.
5. `blocked_pending_locator` — требование известно или вероятно, но прямое доказательство конкретного locator отсутствует/противоречиво.

`official_card_verified` никогда не повышается автоматически до `official_clause_verified`.

## Production gate

Для числового или императивного production-правила обязательно:

- действующая применимая редакция документа;
- конкретный locator: пункт, подпункт, таблица или приложение;
- прямое чтение текста locator;
- отсутствие более позднего изменения, затрагивающего locator;
- совпадение класса объекта и области применения;
- отсутствие unresolved/blocker состояния.

Поисковый сниппет, карточка документа, пересказ, вторичная копия или совпадение нескольких неофициальных сайтов не заменяют прямое чтение locator.

## Маршрутизация по классам объектов

Основные теги:

- `GENERAL` — общие нормы, загружаются только при совпадении предмета регулирования;
- `IZHS` — одноквартирные жилые дома в области СП 55;
- `MKD` — многоквартирные жилые здания;
- `PUBLIC` — общественные здания;
- `INDUSTRIAL` — производственные/складские объекты;
- `TRK` — торгово-развлекательные комплексы;
- `FIRE` — пожарная безопасность, поверх функционального профиля в пределах применимости;
- `STRUCTURAL`, `CLIMATE`, `THERMAL`, `LIGHTING`, `ROOF`, `SITE` — предметные слои.

Правило загрузки: функциональный класс объекта выбирается первым. Общие и предметные документы подключаются вторым слоем только при совпадении области применения. Специальный документ другого функционального класса не подключается без явного нормативного основания/cross-reference.

## Авторитетные внешние источники

Библиотека не зеркалирует полный текст СП/ГОСТ в репозиторий. Она хранит официальные карточки, locator'ы, статусы доказательств и при наличии — контрольные сведения о полученном официальном файле. Это исключает подмену редакций и ненужное распространение полного текста.

Приоритет проверки: официальный нормативный источник/орган -> прямой текст действующей редакции -> авторизованный ГАРАНТ/КонсультантПлюс как независимая текстовая сверка. Вторичные источники используются только как резерв для поиска и корреляции, но не для production-доказательства.

## Fail-closed

Если прямой текст locator недоступен, противоречив или невозможно доказать его связь с действующей редакцией, карточка сохраняется, но соответствующий locator получает `blocked_pending_locator`. Никакие значения из такого locator не должны генерироваться в BIM-модель.
